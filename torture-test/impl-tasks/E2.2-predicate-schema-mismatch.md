# E2.2: predicate/host-profile schema mismatch blocked ALL real Tier-1 cases; vacuous GREEN on --include-real

First real Tier-1 launch (campaign-20260807T145400540Z, `--tier1
--include-real`): terminal in 0.1s, VERDICT GREEN, 4 scripted PASS —
and ALL 24 real cases NOT_RUN(predicate). Zero tokens spent, zero real
runs launched. Two defects:

1. **Schema mismatch.** Case predicates (tier1.jsonl `requires`) test
   e.g. `toolchains.python3 == true` / `toolchains.node == true`, but
   `torture-test/var/w0/host-profile.json` (written by
   tt-verify-environment) stores toolchains as OBJECTS under partly
   different keys: `"python3": {present: true, ...}`, `"node": {...}`,
   `"rust/cargo"`, `"java+maven"`, `"go"`. Evidence from state.json:
   `{"predicate":"toolchains.python3","expected":true,"observed":...}`
   fails on every case. E2's predicate resolver and W0.0's profile
   schema were never integration-tested against each other.
2. **Vacuous GREEN.** An `--include-real` campaign in which EVERY
   real case is predicate-blocked still reports GREEN exit 0. Same
   fail-open class as the all-skipped validate-all defect (FIX6).

## Work

1. Pick ONE canonical contract and enforce it end-to-end. Recommended:
   predicates address `toolchains.<name>.present` (boolean leaf) with
   the profile's actual key names; the resolver supports dotted paths
   into objects. Update EITHER the resolver OR the tier1.jsonl
   predicates (and tier0 real cases if they share the bug) so they
   agree; document the contract in case.schema.json's predicate field
   description and in CONTRACT.md if it mentions predicates.
2. Add the integration test the gap proves is missing: controller
   predicate evaluation against the REAL host-profile.json produced by
   tt-verify-environment on this machine — every tier1 real case's
   requires must evaluate TRUE here except honestly-absent
   capabilities (verify hermes/pi probes are in the profile; if W0.0
   never probes pi/hermes presence, add those probes — spec 01 makes
   pi/hermes operator-preconfigured, so the profile must RECORD their
   presence, never install).
3. Fail-closed rule: when --include-real is given and >0 real cases
   exist but 0 real cases actually LAUNCH (all predicate-blocked or
   otherwise skipped), the campaign verdict must be a distinct
   non-green failure (infra, exit 2) naming the cause. Bare mode
   (no --include-real) keeps its pending-real GREEN semantics.
4. Prove: (a) `./run-torture-test --tier1` bare still GREEN twice;
