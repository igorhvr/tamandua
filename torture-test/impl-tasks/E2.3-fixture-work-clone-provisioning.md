## Findings (US-008 real run; operator directive — collected, NOT fixed in product code)

Per the operator directive, the single authorized real run's observations
of the tamandua PRODUCT are recorded here faithfully. No tamandua
product code was changed in this run; these are handed off for review. Two findings were surfaced:

1. **Token attribution is delivered asynchronously AFTER terminal — and
   carries no step/round/usage identity.** `tamandua` reports a run
   `status='completed'` before the scheduler's separate bookkeeping step
   finalises the work round's usage;
   `runs.tokens_spent` / `run.tokens.updated` events land seconds later,
   and every event carries only `{runId, workflowId, tokenDelta,
   tokensSpent}`. `tamandua` never emits a
   `harness.usage.captured` event, so there is no per-usage/step/round
   observation identity to map oracle findings to specific harness
   rounds. A controller sampling at the completion instant sees false
   zeros (the O3z/O11 zero-token findings in US-008 were this race) and
   can only attribute spend at run granularity. The controller
   compensates entirely within torture-test/ (bounded token-settle, and
   O11's per-usage mapping gated on `usages.length > 0`) — but richer,
   identity-bearing token events would be a tamandua product improvement.
2. **O8_SEEDED_TEST_CHANGED is by-design, not a defect.** The `W1.L1`
   do-now task legitimately extends the pre-seeded `tests/test_dates.py`;
   O8's strict seeded-test-immutability contract flags that edit by
   design (pinned by O8's own self-test). This yields a single honest
   `PRODUCT_FAIL` exit-1 finding on an otherwise-clean, `TEST_INFRA_FAIL=0`
   run — a documented fixture/oracle design tension (the harness is fine;
   a future TT task that must not modify its pre-seeded test would avoid
   it). This is a torture-test design note, not a tamandua product issue.

The real run otherwise exposed several latent torture-test-only
oracle/harness-infra defects (async token settle, O8 tracked-tree +
rebase + mode-semantics reconciliation, DB-schema + workflow-catalog
prerequisites, O11 telemetry calibration) that were FIXED within
torture-test/ — see the US-008 progress-log record.
