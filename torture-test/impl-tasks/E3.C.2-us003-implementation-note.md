## What the guard asserts (bounded, hermetic)

1. **Per-worktree scope-unit derivation** — executes the tool's own
   `scope_suffix_for_root()` (extracted from the audited file, sourced in a
   throwaway bash) with two different repo-root inputs: two distinct 8-hex
   suffixes, unit names `tamandua-tt-<kind>-<suffix>` that never equal the
   bare fixed `tamandua-tt-<kind>`, and the SAME root → the SAME suffix
   (stability: a per-run random suffix would break stop isolation).
   Structural pins: `cmd_start` builds
   `tamandua-tt-$name-$scope_suffix` from `scope_suffix_for_root "$TT_REPO_ROOT"`
   and never falls back to the old fixed `tamandua-tt-$name`; the helpers
   `scope_suffix_for_root()` / `scope_unit_is_ours()` exist.
2. **Cross-worktree stop isolation** — structural: every `systemctl --user
   stop` site in daemon-control shares its if-block segment with
   `scope_unit_is_ours` (cmd_stop) or the derived `scope_unit` (cmd_start),
   and no stop site targets a bare `tamandua-tt-<kind>.scope` literal.
   Behavioral (safe simulated systemd): fake `systemctl`/`systemd-run` shims
   on PATH + planted provenance (high unused ports 25334+ → the idempotent
   "already stopped" path — no real daemon, no real systemd, no tamandua
   invocation) → a recorded FOREIGN unit (`tamandua-tt-scripted-00000000`)
   and the LEGACY bare unit (`tamandua-tt-scripted`) are REFUSED (never
   stopped), while this worktree's derived unit IS stopped (positive control
   proving the shims were live and the tool still cleans up its own scope).
3. **Bounded port-free wait** — structural: `cmd_start` honors
   `TT_DAEMON_PORT_WAIT_SECONDS`, requires the ports free STABLY across a
   settle, and fails with `refusing to launch into a busy port`. Behavioral
   (in-tree tool only): a self-terminating squatter listener on 5339 (no kill
   site — retry-bind + `setTimeout` self-termination) makes `scripted start`
   wait out a 2s bound and fail with the busy-port diagnostic; the daemon pid
   file is untouched (no half-up daemon). The arm is skipped (with the
   structural pins still failing) when `TT_DC_TOOL` points at the pre-fix
   tool, so the RED proof never launches a real daemon.
