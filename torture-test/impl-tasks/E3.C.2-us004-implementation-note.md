## Root-cause note (deliverable, embedded in this report)

**Why E3.C.1's own bare-tier1 GREEN x2 proof passed with the breakage —
proof-protocol gap: no concurrent-run isolation guard.**

The E3.C.2 scripted-start regression is a *race*, not a deterministic
single-run defect: the systemd scope unit name `tamandua-tt-scripted` and the
scripted ports 5334/5338/5339 were FIXED and shared by every worktree, and
daemon-control issued *unconditional* `systemctl --user stop
tamandua-tt-scripted.scope` at three sites (cmd_start pre-launch, cmd_stop
idempotent residual, cmd_stop Step 5). A concurrent run's stop therefore
SIGTERM'd another run's in-flight `systemd-run` launch (bash prints
`Terminated <cmd>`, exit 143, `run-scripted-scenario:285` reports start
failed). The failure only manifests when two runs destructively interleave on
the shared scope/ports.

E3.C.1's own proof passed because its proof windows did **not** destructively
interleave with the concurrent worktree campaigns (865/866) that were already
driving the same fixed scope/ports. Timeline evidence: 866 MACP2
(`c34941b1`) was live at 14:54:56 while E3.C.1 committed at 14:55:15 and the
failing campaign started 14:55:44 — i.e. the two sides' daemon windows
collided *after* the proof had already run clean. The proof protocol had NO
guard asserting that a bare-tier1 GREEN result is only meaningful in
isolation (or under verified per-worktree isolation) — a proof-protocol gap.

**Guard added (US-003):** `torture-test/self-tests/tier1-daemon-control-scope-isolation.test.ts`
— 7 bounded hermetic assertions pinning (1) per-worktree scope-unit
derivation, (2) cross-worktree stop isolation (foreign/legacy scopes
refused), (3) bounded port-free wait refusing busy ports. Red-then-green
proven against the pre-fix tool (74f4d332: 6 fail/1 skip) and GREEN on the
fixed tool (7/7). Evidence: `E3.C.2-us003-evidence/` (green-run.txt,
red-run-prefix-74f4d332.txt, battery-result.txt).

## Fix summary (US-002; E3.C.1 US-004 intent preserved, nothing reverted)

- **Per-worktree scope unit name:** `tamandua-tt-<kind>-<8-hex cksum of
  TT_REPO_ROOT>` via `scope_suffix_for_root()` (mirrors the T2.1 US-009
  pattern). Used in cmd_start systemd-run --unit + pre-launch
  stop/reset-failed, provenance scopeUnit, verify_cgroup, and both cmd_stop
  cleanup paths. The old bare fixed name is never used (hygiene scanner
  asserts no `tamandua-tt-<kind>.scope` literal remains).
- **Ownership gate:** `scope_unit_is_ours()` — cmd_stop idempotent residual +
  Step 5 REFUSE to stop any recorded scope that is not this worktree's
  derived unit (legacy/fixed name or foreign worktree unit never stopped).
- **Bounded port-free wait:** `TT_DAEMON_PORT_WAIT_SECONDS` (default 10s,
  env-overridable) — waits for the kind's fixed ports to be free STABLY (2s
  settle), refuses with `refusing to launch into a busy port` on bound
  exhaustion; a concurrent worktree daemon can no longer be SIGTERM'd but
  also can't be raced into EADDRINUSE.
- **Stale pidfile clearing:** a dead/empty `tamandua.pid` left by a killed
  daemon is removed before the pid-wait (ports already proven free).
- **US-004 session-2 fix (deterministic W2.21 race):** `stop_cli_auto_daemon`
  — cmd_stop (missing-provenance / idempotent / main Step 0) and cmd_start
  (before the bounded port-wait) ALSO stop THIS worktree's own CLI-auto-
  started daemon (from `workflow run` -> ensureDaemonControlAvailable ->
  startDaemon: no provenance, no systemd scope, recorded only in the state-
  dir tamandua.pid). Identity-verified + per-worktree: pid alive, != prov_pid,
  /proc cwd under TT_REPO_ROOT + cmdline tamandua, environ TAMANDUA_STATE_DIR
  == this worktree's state dir, ABA startTime re-verified before each signal.
  Foreign-worktree daemon or unverifiable pid REFUSED, never stopped. Kill
  lines reuse the `$lingering_pid` registered-registry shape (hygiene scanner
  45/45). Nothing from E3.C.1 US-004 reverted.
- E3.C.1 US-004 pieces UNTOUCHED: IDENTITY_TOOL, verify_recorded_identity,
  verify_listener_target, verify_process_tt_owned, provenance startTime,
  production guards, guard_kind_containment. Nothing reverted.

## Scheduling note

The proof battery requires the fixed scripted ports (5334/5338/5339) to be
free. At proof time the concurrent T2.1 worktree (865) was running its own
scripted campaigns on those ports; per the E3.C.2 design (per-worktree scope
names + port-wait) the proofs must not destructively interleave with the
concurrent run, so the battery was executed in the port-free window after the
concurrent campaign sequence completed. This is itself evidence of the fix:
the campaigns coexisted and the fixed-ports contention serialized cleanly
instead of TERMing each other.

## ⚠ FINDING (session 1 of US-004, 2026-08-18 ~09:38Z) — W2.21 restart race, DETERMINISTIC

While running the Proof-1 battery, bare `./run-torture-test --tier1` fails on
W2.21-admission **even in a fully clean standalone run** (`--case W2.21`,
ports free, no scope, no controller) — and the W2.23a/b/c failures are the
cascade (their harness daemon start refuses on the orphan left by W2.21).

**Root mechanism (evidence: `E3.C.2-us004-evidence/w221-standalone-*`):**
1. W2.21 Step 2 `workflow run` → CLI `ensureDaemonControlAvailable` →
   `startDaemon()` spawns a PLAIN background daemon (no systemd scope, no
   daemon-control provenance) holding control port 5339.
2. W2.21 Step 4 `daemon-control scripted stop` kills ONLY the provenanced
   scope; the CLI-started daemon (no provenance/scope) SURVIVES.
3. Step 4 `daemon-control scripted start` → the E3.C.2 bounded port-wait sees
   5339 busy (our own orphan) → after 10s → `refusing to launch into a busy
   port` → run.mjs assert fails → PRODUCT_FAIL. An orphaned daemon (PPID 1,
   cwd=this worktree, HOME=var/home-scripted) is left holding 5339.
4. Pre-E3.C.2 the same race existed but was MASKED: the restart's new daemon
   hit EADDRINUSE on 5339 yet the run stayed scheduled by the CLI daemon, so
   Step 5's poll saw completion → PASS. The E3.C.2 port-wait turned the
   latent race into a deterministic, visible refusal.

**Required fix (IMPLEMENTED in session 2 — see below):**
`daemon-control` cmd_stop (and the idempotent/residual path) must ALSO stop
this worktree's own CLI-auto-started daemon — identified by the scripted
state dir's `tamandua.pid` whose /proc cwd/env matches this worktree's
`var/home-scripted` — so the Step-4 restart finds 5339 free. This stays
within E3.C.1's intent (kills scoped to explicit recorded/verified targets:
the pidfile PID verified against this worktree's state dir; a foreign
worktree's daemon is NEVER touched) and must keep
`tier1-kill-ancestry-hygiene.test.ts` green (new kill site needs the
recorded-identity gating the scanner audits). Alternative if unfixable: make
the scenario's Step-2 CLI auto-start use daemon-control — but that is a
product (src/) change, OUT of the torture-test/ confinement.

Also observed: `E3.C.2-us004-evidence/tier1-run1-collision-report.txt` +
`tier1-direct-collision-report.txt` — two earlier tier1 attempts that
collided with the concurrent 865 activity; their W2.21 stderr shows the SAME
busy-5339 refusal (our own orphan, not 865's), i.e. the collision reports are
the same root cause. The E3.C.2 serialization itself worked (clean refusal,
no TERM) in all cases.

## US-004 session 2 (2026-08-18) — fix landed: stop_cli_auto_daemon

The deterministic W2.21 restart race is now FIXED in
`torture-test/bin/daemon-control` (commit e4647463, "feat: US-004 -
daemon-control stops this worktree's own CLI-auto-started daemon"):

**New helper `stop_cli_auto_daemon <kind>`** — reads the kind's state-dir
`tamandua.pid` (the CLI daemon's ONLY recorded registry — it has no
daemon-control provenance and no systemd scope) and, when the pid is alive,
is NOT the provenance pid, and identity-verifies as THIS worktree's own
daemon, stops it with the E3.C.1 US-004 ABA gating:
- `verify_process_tt_owned` — /proc cwd under TT_REPO_ROOT + cmdline
  contains tamandua (fail-closed);
- /proc environ `TAMANDUA_STATE_DIR` must equal this worktree's state dir —
  the per-worktree discriminator (a foreign worktree's daemon has a
  different state dir and is REFUSED, never stopped);
- startTime identity captured via `IDENTITY_TOOL --get` and re-verified
  before SIGTERM and before SIGKILL (ABA-safe).
A foreign-worktree daemon or an unverifiable pid is REFUSED, never
signalled. Kill lines reuse the `$lingering_pid` registered-registry shape
so `tier1-kill-ancestry-hygiene.test.ts` stays green (45/45).

**Call sites:**
- `cmd_stop` missing-provenance path — a CLI daemon (no provenance by
  construction) may be the only port holder; stop it before declaring the
  ports unknown.
- `cmd_stop` idempotent "already stopped" path — belt-and-suspenders
  (a live CLI daemon invisible to the provenance paths).
- `cmd_stop` main stop path (Step 0, before the provenance steps) — the
  W2.21 case: provenance records the harness daemon (dead), the CLI daemon
  holds 5339; Step 0 stops it so Step 4's restart finds 5339 free.
- `cmd_start` before the bounded port-wait — the w2.23c case: a scenario
  launched `workflow run` with the daemon down (CLI auto-start), then calls
  `daemon-control scripted start`; the CLI daemon is stopped instead of
  refusing on its busy port.
