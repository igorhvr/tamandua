# tt-poly-lite — Two-Language Storm Monorepo Fixture

A tamandua torture-test fixture that combines the python/ (schedlib-poly)
and ts/ (expense-tracker-poly) subtrees into a single monorepo. Used by
Tier-1's storm and capacity-scaled storm variants.

## TEST_CMD

```bash
./run-all-tests
```

Expect ~3–4 minutes wall time with both suites bootstrapped.

## Requirements

- **python3** on PATH (python3 or python)
- **node** (≥ 22) on PATH
- No other toolchains required — the fixture is self-bootstrapping and
  works offline after initial `npm install`

## Junk Probes

This fixture carries **intentional untracked junk** per spec 02's three-class
junk-probe requirement. None of the classes is gitignored — oracles verify they
appear as untracked in `git status` so the dirty-tree gate tolerates them
while rejecting tracked drift.

| Artifact | Class | Location | Notes |
|---|---|---|---|
| `__pycache__/` | Seeded/deterministic | python/ | Synthetic marker planted at provisioning (byte-identical to fixtures-src reference) |
| `.pytest_cache/` | Regenerated | python/ | pytest cache (`.gitignore` removed at end of each run) |
| `package-lock.json` | Regenerated | ts/ | Generated by npm install |
| `node_modules/` | Regenerated | ts/ | Contains `.tamandua-stray-probe.txt` after pretest |
| `.flaky_counter` | Regenerated | python/ | Counter file for POLY-FLAKY-P1 alternator |
| `operator-notes.local` | Inert | root, python/, ts/ | Fixed byte-content, never touched |

See `JUNK-IS-INTENTIONAL.md` and `README-JUNK.md` for detailed
documentation on each probe.

## Integrity Invariants

1. **Baseline green:** `./run-all-tests` exits 0 on the pristine tree
2. **Seed isolation:** each seed applies cleanly to baseline
3. **Fix correctness:** each fix patch restores green when applied on
   top of its seed
4. **Junk presence:** all junk probes exist and are untracked after one
   full test run
5. **Inert junk integrity:** every `operator-notes.local` is byte-identical
   to the committed sampler
6. **Deterministic builds:** two consecutive runs of `build-golden.sh`
   produce identical commit hashes
