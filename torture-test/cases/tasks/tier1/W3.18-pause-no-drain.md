Real pi run: feature-dev-merge-worktree on tt-ts. This lifecycle probe tests pause-without-drain during an active implement story.

**Probe sequence:** The controller will pause the daemon without drain while a developer agent is mid-implement (story claimed, step running), hold for 10 minutes, then resume.

### Feature: Custom Expense Categories

Add user-managed expense categories to the expense tracker: categories can be added, renamed, and removed, and newly added categories appear in the filter dropdown.

**Acceptance Criteria:**
1. Categories become dynamic data instead of a hardcoded list: `src/store.ts` (and `src/types.ts` as needed) gain a categories collection seeded with the five current defaults (Food, Transport, Utilities, Entertainment, Other) so existing expenses keep working, with store methods `addCategory(name)`, `renameCategory(oldName, newName)`, and `removeCategory(name)`
2. Backing API endpoints in `src/server.ts`: `GET /api/categories` lists categories, `POST /api/categories` adds one, `PUT /api/categories/:name` renames one, `DELETE /api/categories/:name` removes one; expense create/update validation accepts any current custom category
3. Category management UI in `public/index.html` + `public/app.js` with add/rename/remove controls (frontend functions named e.g. `addCategory` / `renameCategory` / `removeCategory`), and the add-expense and filter dropdowns are populated dynamically so a newly added category appears in the filter dropdown immediately
4. Tests in `src/store.test.ts` / `src/server.test.ts` named with the `FEAT-T1` tag and the word category (e.g. `adds, renames and removes custom categories (FEAT-T1)`, `category filter dropdown includes new categories (FEAT-T1)`) covering add/rename/remove through the API, expense validation against custom categories, and dropdown population

## Verifying

Run the fixture's suite command from the fixture root: `npm test`. A correct implementation makes the full suite pass, including the new category tests.
