## Task

### Feature: Expense CSV Export

Add a CSV export capability to the expense tracker: a `GET /api/expenses/export` endpoint that returns all expenses as a CSV download with correct comma/quote escaping, plus a download button in the frontend.

**Acceptance Criteria:**
1. New pure helper module `src/export.ts` with a `toCsv(expenses)` function that renders the header row `id,description,amount,category,date` and one row per expense (same field order as the existing expense JSON)
2. Correct CSV escaping in `toCsv`: any field containing a comma, a double quote, or a newline must be wrapped in double quotes with embedded double quotes doubled (e.g. a description like `Lunch, team` or `7" monitor` must round-trip as a single field, never split into extra columns)
3. `src/server.ts` exposes `GET /api/expenses/export` returning the CSV with `Content-Type: text/csv` (a content-disposition filename hint such as `expenses.csv` is fine); register it alongside the existing `/api/expenses` routes
4. Download button in the frontend: `public/index.html` gets an Export/Download CSV button wired in `public/app.js` so clicking it downloads the expenses as a `.csv` file (e.g. a link/button using the `download` attribute or a Blob with a `.csv` filename)
5. Tests: endpoint tests in `src/server.test.ts` (plus helper tests in `src/export.test.ts`) named with the `FEAT-T3` tag (e.g. `exports all expenses as CSV with text/csv content type (FEAT-T3)`, `escapes commas and quotes in CSV fields (FEAT-T3)`) covering the endpoint shape, the `text/csv` Content-Type, the header row, and comma/quote escaping

**This is a cross-cutting ≥5-file feature:** it spans the new export module, the server, the frontend, and tests (`src/export.ts`, `src/server.ts`, `public/index.html`, `public/app.js`, test files). The feature-dev-merge-worktree planner should decompose this into stories and implement them sequentially.
