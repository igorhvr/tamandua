### Feature: Recurring Expense Support

Add support for recurring expenses with configurable frequency (weekly, monthly, yearly). This is a cross-cutting feature touching multiple modules.

**Acceptance Criteria:**
1. `Expense` interface extended with optional `recurring` field: `{ frequency: 'weekly' | 'monthly' | 'yearly', startDate: string, endDate?: string }`
2. New module `src/expense/recurring.ts` with a function `generateOccurrences(expense, from, to)` that returns an array of virtual `Expense` objects for each occurrence in the date range
3. `src/expense/calculator.ts` updated to include recurring occurrences when computing category totals and monthly summaries
4. `src/expense/store.ts` updated with a `getRecurringExpenses()` method that filters stored expenses for those with a `recurring` field
5. `src/expense/export.ts` updated to optionally include an "Occurrence Date" column for recurring-generated rows
6. Full test coverage for the new module and updated integration points

**This is a cross-cutting ≥5-file feature:** it spans the interface, new module, calculator, store, and export. The feature-dev-merge-worktree planner should decompose this into stories and implement them sequentially.

## Boundaries

- Stay within `src/expense/`, `src/util/`, and test files
- Do not modify `operator-notes.local` or files under `seeds/` or `probes/`
- Keep backward compatibility: existing expenses without `recurring` field must continue to work
