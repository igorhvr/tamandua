### BUG SYMPTOM (red-herring archetype)

Users report that the monthly expense summary (`getMonthlySummary`) returns incorrect totals — it double-counts expenses that fall on month boundaries. For example, an expense on January 31st is counted in both January and February summaries.

The natural place to look is the month-aggregation logic in `src/expense/calculator.ts`, but the actual root cause is in `src/util/date.ts` — the `getMonthKey` function uses a flawed date-parsing path that mishandles timezone offsets and local date boundaries, producing wrong month keys for dates near the end of the month. Fixing the aggregation will paper over one symptom but leave the root cause and break date-range queries elsewhere.

**This is a red-herring:** the symptom points at `calculator.ts`, but the defect is in `date.ts`. You must investigate past the obvious target.
