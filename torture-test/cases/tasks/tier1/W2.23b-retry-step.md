# W2.23b: Hostile custom workflow — dangling on_fail.retry_step

Scripted scenario (~0 tokens) testing workflow validation: install a custom workflow with a dangling `on_fail.retry_step` reference (pointing to a non-existent step), then attempt to run it.

## Task

1. Install a purpose-built hostile custom workflow whose workflow.yml contains an `on_fail.retry_step` that references a step id that does not exist anywhere in the workflow
2. Launch `tamandua workflow run <hostile-workflow-id> "test task"`
3. Assert the validator or runtime rejects the workflow with an actionable diagnostic at the EARLIEST phase that can see the defect — the retry_step target must be validated
4. Assert no doomed run row is created (or if a run IS created, it fails with a clear diagnostic rather than crashing the daemon or hanging)

## Boundaries

- This is a scripted (~0 token) scenario running under the hermetic scenario harness
- Never touch the live daemon (33xx ports)
- The hostile workflow is isolated to the scenario's temp state dir
