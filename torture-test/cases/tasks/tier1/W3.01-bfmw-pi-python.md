### BUG SYMPTOM (red-herring archetype)

Users report that the `schedule_overlap` function in `src/schedlib/conflicts.py` detects overlapping events incorrectly when one event ends exactly when another starts. For example, an event 09:00–10:00 and another 10:00–11:00 are flagged as overlapping when they should not be.

The natural place to look is the overlap logic in `conflicts.py`, but the actual root cause is in `src/schedlib/dates.py` — the `parse_time` helper normalizes boundary timestamps inconsistently, introducing a one-second offset that cascades into the overlap detector. Fixing the overlap detector will silence one symptom but leave the root cause and break other time-dependent features.

**This is a red-herring:** the symptom points at `conflicts.py`, but the defect is in `dates.py`. You must investigate past the obvious target.
