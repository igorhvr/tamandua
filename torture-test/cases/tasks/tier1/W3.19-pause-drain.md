# W3.19: Lifecycle Probe — Pause --drain during active story

Real hermes run: feature-dev-merge-worktree on tt-ts. This lifecycle probe tests pause-with-drain while an implement story is claimed and running. Drain must let the in-flight story's step complete, then park WITHOUT dispatching the next story — never produce a draining_pause wedge (empty-loop-state fossil). Resume dispatches the next story.

### Feature: Monthly Expense Dashboard

Add a monthly expense dashboard to the expense tracker: a per-month view with a bar chart drawn via the Canvas API (no chart library) and month navigation.

**Acceptance Criteria:**
1. A dashboard page/section in the frontend (`public/index.html` + `public/app.js`, or a dedicated `public/dashboard.html` if you prefer) showing monthly expense totals
2. The dashboard renders a bar chart with the Canvas API directly — a `<canvas>` element plus `getContext('2d')` drawing code (axes, bars, labels). NO external chart library is allowed: no Chart.js/chartjs, no d3.js, no highcharts, no plotly — plain Canvas API only
3. Month navigation: previous/next month controls (e.g. a month label with ‹ › buttons) that change the displayed month and re-render the chart for the selected month; monthly aggregation is backed by a store/server summary (e.g. `getMonthlyTotals(year, month)` in `src/store.ts` and/or a `/api/expenses/monthly` endpoint in `src/server.ts`)
4. Tests named with the `FEAT-T2` tag and dashboard/chart terms (e.g. `monthly dashboard aggregates totals per month (FEAT-T2)`, `bar chart data groups expenses by month (FEAT-T2)`) covering monthly aggregation and (if server-side) the summary endpoint

## Verifying

Run the fixture's suite command from the fixture root: `npm test`. A correct implementation makes the full suite pass, including the new dashboard tests.

## Boundaries

- Work within `src/`, `public/`, and test files
- Do not modify `operator-notes.local` or files under `seeds/` or `probes/`
- This is sized for 2-3 stories so the drain can operate between stories
