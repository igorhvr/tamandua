# W2.23a: Hostile custom workflow — non-compiling expects regex

Scripted scenario (~0 tokens) testing workflow validation: install a custom workflow with a non-compiling `expects` regex, then attempt to run it.

## Task

1. Install a purpose-built hostile custom workflow whose workflow.yml contains an `expects` field with a syntactically invalid regex (e.g., an unmatched parenthesis or invalid escape sequence)
2. Launch `tamandua workflow run <hostile-workflow-id> "test task"`
3. Assert the validator or step-ops layer rejects the workflow with an actionable diagnostic at the EARLIEST phase that can see the defect — either:
   a. At install time (workflow validation catches the regex), OR
   b. At step completion time (the expects regex fails to compile)
4. Assert no doomed run row is created, no daemon crash occurs, and the rejection message clearly identifies the malformed regex

## Boundaries

- This is a scripted (~0 token) scenario running under the hermetic scenario harness
- Never touch the live daemon (33xx ports)
- The hostile workflow is isolated to the scenario's temp state dir
