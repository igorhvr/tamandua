Real pi run: feature-dev-merge-worktree on tt-ts. This lifecycle probe tests `workflow fail --force` on a live run, then `workflow resume` on the same run.

### Feature: Recurring Monthly Expenses

Add recurring monthly expenses to the expense tracker: a recurring flag on the expense model, a generation endpoint that is idempotent per calendar month, and a recurrence indicator in the frontend.

**Acceptance Criteria:**
1. `src/types.ts`: `Expense` gains an optional `recurring` field (e.g. `recurring?: boolean` or `recurring?: { monthly: boolean; day?: number }`) — the literal field name must be `recurring`
2. `src/store.ts` supports recurring expenses: `getRecurringExpenses()` filters expenses with the recurring flag, and generated-instance insertion is duplicate-safe (a per-month generation guard such as `lastGeneratedMonth` so a second generation in the same calendar month inserts nothing)
3. `src/server.ts` exposes `POST /api/expenses/recurring/generate`: generates this calendar month's instance(s) for each recurring expense. IDEMPOTENT per calendar month: calling it twice in the same month produces no duplicate expenses (the second call is a no-op); calling it in a new month generates again
4. Frontend (`public/index.html` + `public/app.js`): a recurrence indicator on recurring expenses (the 🔄 symbol or an isRecurring badge) and a checkbox/input in the add-expense form to mark a new expense as recurring
5. Tests named with the `FEAT-T4` tag (e.g. `generates monthly recurring expenses once per calendar month (FEAT-T4)`, `recurring generation is idempotent within the same month (FEAT-T4)`) covering the flag round-trip, generation, and the idempotency guarantee
