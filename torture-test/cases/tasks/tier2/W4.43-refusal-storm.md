## Controller note (T2.1 US-010 — re-proof round 5: the round-3 timing fix was a no-op; the running window now comes from the doer's own work)

The honest re-proof's campaign-20260818T202341526Z (fresh var, bare
`--tier2`) FAILED this cell again: **W4.43-refusal-storm PRODUCT_FAIL,
`live run step must be claimed (mid-flight) before the storm`** — the same
assertion the round-3 note above claims was made deterministic. Diagnosis
from the campaign evidence + the scripted runtime:

1. **The round-3 fix premise was wrong.** The `delayed_trailer_ms: 3000`
   added by commit 93aa42aa does NOT extend the step's "running" window.
   The runtime's knob path (`runtime-pi.mjs` `runWorkRound`) calls
   `completeStep` (the CLI `step complete`) FIRST and only then schedules
   the deferred `message_end` — the knob reorders the message_end (token
   usage) event, never the step completion. The step's DB status goes
   pending → running → done at claim/complete time, so the observable
   "running" window is just the claim→complete round (~88ms in the
   failing campaign: `step.running 21:12:40.478 → step.done 21:12:40.566`).
   The round-3 "claim-to-complete 845ms" observation was the LIVE RUN's
   claim→complete (the run row), not the STEP's running window — the poll
   that missed is the cell's 100ms step-status poll, which an 88ms window
   can fall between.
2. **Fix (premise correction, no assertion weakened): the doer's work now
   takes 3s.** behaviors.json's doer carries `commands: ["sleep 3"]` —
   the scripted runtime executes behavior commands BETWEEN the claim and
   the step-complete call (`applyBehaviorActions` runs before
   `completeStep`), so the step is observably "running" for a
   deterministic ~3s window that a 100ms poll cannot miss. This is the
   mechanical equivalent of a slow agent round — the exact condition the
   cell always assumed ("the live run step is mid-flight"). The storm
   still lands inside the live run's window (10 refusals in <10s), the
   claim-to-complete assertion (<60s) still holds (3058ms observed
   standalone), and the run completes + follow-up launch are unchanged.
3. Verified standalone: `run-scripted-scenario scenarios/w4.43/refusal-storm`
   PASS (10 refusals, 10 distinct diagnostics, storm 845ms, live run
   completed, claim-to-complete 3058ms, zero tokens). The cell is GREEN in
   the final re-proof campaigns on the fixed tree.
