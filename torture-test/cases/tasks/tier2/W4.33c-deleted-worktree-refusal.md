# W4.33c: Resume a run whose worktree was deleted — diagnosable refusal, leg (c) (gating)

Real pi run: bug-fix-merge-worktree (bfmw) on the **tt-ts** fixture
(`TEST_CMD` = `npm test`). Resume-composition leg (c) of spec 08 §G W4.33:
the run's worktree is deleted out-of-band mid-run (the W4.13 composition),
and the subsequent resume must produce a **diagnosable refusal, never a
silent fallback into the wrong directory** (DC25's contamination fossil).

## Seeded defect (BUG-T2 — what the fixture actually contains)

The tt-ts seed `BUG-T2` (SEEDS.md catalog) implants an **A2 two-module
date-handling bug** (`src/server.ts` ISO-normalizes POST dates,
`src/store.ts` `getByDateRange` compares them naively → exact-date queries
miss day-boundary expenses). Dormant in the baseline; fix spans both files.

## Injection / operator choreography (no probe_sequence)

The worktree deletion and the resume are OPERATOR actions — there is no typed
probe op for deleting a run worktree, and the resume-refusal outcome would
trip O16's hardcoded resume-completes judgment, so this leg deliberately
declares `probe_sequence: null` and carries the full protocol here (see
cases/tier2-traceability.md machinery deltas):

1. Launch the bfmw run normally.
2. Mid-run (armed on `step:developer:running`), delete the run's worktree
   OUT-OF-BAND: `rm -rf` the contained run's worktree path (resolve it from
   the contained DB `runs.context.worktree_path`; verify the path is under
   the contained `TAMANDUA_WORKTREE_ROOT` before deleting — target guards per
   the wave-4 injection discipline).
3. The run fails (or the next dispatch diagnoses the missing worktree) with a
   diagnosable error naming the missing worktree.
4. Operator runs `workflow resume <run-id>` on the contained env.

## Expected (O10 unless noted)

- **Diagnosable refusal, not a silent fallback:** the resume must NOT silently
  fall back into a wrong directory (a recreated path elsewhere, the origin
  clone, or the operator's own checkout — DC25's contamination fossil). The
  refusal (or re-provisioned-worktree recovery) must be loud and name the
  deleted worktree. A silent re-point into the wrong directory is the S1.
- **Run reality reflected:** `run_worktrees` state must reflect the deletion
  (O6-style truthfulness) — no phantom worktree row claiming the deleted
  path is live.
- The corridor terminates: either the run stays failed with the diagnosis, or
  a re-provision path recovers it — never an infinite retry loop against the
  missing path.
