# W4.30: Detached-HEAD origin — launch-time diagnosable refusal, never a mangled ref

Real pi run: bug-fix-merge-worktree (bfmw) on **tt-ts**, seed **BUG-T2** (the
SEEDS.md catalog's A2 two-module date-handling defect: `server.ts` stores
full ISO datetimes while `store.ts` `getByDateRange` compares with
`localeCompare`, so exact-date queries miss day-boundary expenses). Spec 08 §F
W4.30 (T1): the worktree-ORIGIN repo is checked out **detached**
(`git branch --show-current` empty → `ORIGINAL_BRANCH` empty → merger target
`refs/heads/` garbage corridor). The expected outcome is a **launch-time or
setup-time diagnosable refusal** — NEVER a mangled/created bogus ref.

## What the fixture actually contains

- Seed **BUG-T2** implants the date-handling defect across `src/server.ts`
  and `src/store.ts` (dormant: the suite never POSTs a `date` field or uses
  `?startDate=`/`?endDate=` query params).
- The case's **reset hook** (`cases/hooks/reset-w4.30-detached-head-origin.sh`)
  detaches the working clone's HEAD (`git checkout --detach HEAD`) after
  provisioning and verifies `git branch --show-current` is empty (fail-closed).

## The corridor under test

The launch path (`createRunWorktree`) captures the origin's branch with
`git branch --show-current`; with the origin detached, `ORIGINAL_BRANCH` is
empty. The merger target would degenerate to the `refs/heads/` garbage
corridor. The product must REFUSE at launch/setup time with a **diagnosable**
error naming the detached-HEAD condition — and must NEVER:

- create a bogus `refs/heads/` target ref,
- mangle an existing ref,
- land anything against a garbage branch name,
- hang or retry silently.

The current product refuses with
`origin repository is in detached HEAD state and no --worktree-origin-ref was
provided` (thrown before any worktree/ref mutation) — pin THAT corridor: the
run fails loudly at launch, the refusal is diagnosable, and no ref is
created/moved.

## Expected

- **Launch-time or setup-time diagnosable refusal** naming the detached-HEAD
  condition; the run terminates with the refusal recorded.
- **Never a mangled/created bogus ref:** no `refs/heads/` garbage branch, no
  half-created worktree, no target mutation (asserted from the run's terminal
  evidence + the contained repo state).
- The refusal is deterministic and the diagnosis is surfaced (stderr/status),
  not swallowed into a silent worker_lost-style loop.

## Boundaries

- Work within the tt-ts fixture; the detachment is the INJECTION — do not
  re-attach the origin HEAD during the run.
- Do not modify `operator-notes.local`, `seeds/`, or files under `probes/`.

## Spec-vs-machinery note (documented, not silent)

The detachment is performed by the case's reset hook (task-carried arming —
the W4.05/W4.37 pattern); there is no typed op for detaching the origin HEAD.
The refusal corridor is product behavior pinned by the case. Caps at bfmw p95:
tokens 1M / wall 35 min (p50 floor — the refusal shortens the run, the cap
stays at the honest floor, the W4.33c pattern); `production_duration_floor_ms`
300000.
