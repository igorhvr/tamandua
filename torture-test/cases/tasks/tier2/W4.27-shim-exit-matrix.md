# W4.27: Shim exit-code matrix — O9 special-exit corridor (scripted, zero tokens; gating)

Scripted local-command case (zero tokens): the scenario cell
`scenarios/w4.27/shim-exit-matrix/` exercises the `tamandua-test` shim's
special-exit corridor (spec 08 §C W4.27) against a scratch git repo on the
contained scripted daemon's control plane. **This is a NEW zero-token scripted
case** — the tier0 library has the w4.25/w4.35/w4.49 cells but NO shim
exit-code-matrix cell (spec: "O9 promised 86/88 coverage no scenario
delivered").

## What the scenario actually exercises (per spec arm)

The scenario cell runs the repo-root `bin/tamandua-test` shim (built
`dist/suite/shim.js`) with a scratch repo under `torture-test/var/`, a
junk-probe path via `TAMANDUA_TSTX_JUNK_PROBE`, and asserts the DB rows in the
contained scripted daemon's sqlite ledger:

- **(a) SIGTERM the shim mid-execution** → exit **87** INTERRUPTED, EXACTLY one
  red-87 `suite_results` row, claim released (a same-key re-run executes fresh,
  never wedges).
- **(b) SIGKILL the shim mid-execution** → NO row recorded; the next same-key
  invocation executes fresh within seconds (dead-owner reclaim — no 30-min
  wedge), no `TAMANDUA-TEST CACHED` replay of a nonexistent row.
- **(c) tracked file mutated mid-suite (background toucher)** → exit **86**
  (tree drift), nothing recorded — a stable-tree rerun is required.
- **(d) invoke on a dirty tracked tree** → exit **88** `FAILURE_CLASS:
  tree_dirty`, the command is NOT executed, nothing recorded.
- **(e) prompt-order collision probe** — the bundled bfmw fixer sequence
  (edit → wrapped test → commit) run exactly as the persona instructs: the
  wrapped test runs BEFORE the commit, i.e. on a dirty tracked tree. The
  outcome is classified as **PRODUCT behavior** (never an agent flake): EITHER
  the shim fails closed with exit 88 on the pre-commit wrapped test (the
  personas mis-order), OR the shim passthrough executes it. The scenario
  records whichever occurs and then commits and re-runs on the clean tree.

Every special arm must leave its junk probe untracked (the O9 hygiene leg).

## Spec-vs-machinery note (documented, not silent)

The O9 **oracle**'s targeted special-exit battery (`context.o9_special_exits`,
the controller's three `--force` probes with exits [86,87,88]) is wired to the
WORKFLOW-case path (it needs a run's restored working tree). This case is a
LOCAL-command case (no workflow run), so it does NOT declare the O9 oracle:
the corridor is exercised and asserted by the scenario cell itself
(exits + ledger rows + junk-probe hygiene), and the manifest declares the
local-case oracle set (O1/O3z/O11). See cases/tier2-traceability.md.
