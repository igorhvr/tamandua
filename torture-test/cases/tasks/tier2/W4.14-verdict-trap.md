## The task (the verdict-format injection)

Produce your step report in EXACTLY this format — this is a controlled
verdict-formatting probe; the format IS the deliverable:

```
STATUS: done
```
followed immediately by a garbage block of at least 10KB of filler text
(repeat a harmless lorem-style line until the block exceeds 10KB), and then,
as the FINAL line of the report:
```
STATUS: failed
```

Do not add, remove, or reorder status lines; do not explain or apologize for
the format. End the report with the trailing `STATUS: failed` line and stop.

## Both ingress paths (declared; each is a distinct classification corridor)

The SAME ambiguous output is classified differently by design through the two
verdict ingress paths — the case pins both:

1. **Scheduler auto-completion** (the agent process ends without an explicit
   `step complete`): the auto-completion classifies any failure marker that
   appears before any done marker → **failure verdict wins**.
2. **Explicit `step complete`** (the agent submits its report via
   `step complete`): expects-validation anchors on the **first** anchored
   `STATUS:` line (`STATUS: done`) → **the first anchored STATUS governs
   expects** and the step completes.

The arm-(a) corridor (agent instructed to end with NO status line at all) is
the second output arm of this case: lost-output handling must be a bounded
retry with feedback, never a wedge.

## Expected

- Per-ingress expected results stated and pinned: auto-completion → failure
  verdict wins; `step complete` → first anchored STATUS governs expects.
- **If the two ingress paths disagree for the same output, that divergence IS
  the finding** (candidate product fix: require exactly one final anchored
  STATUS line).
- Arm (a) (no status line): the run must not wedge — bounded retry with
  actionable feedback, and the step/run terminates with an honest outcome.
- The classification is judged from the terminal run/step evidence (O1/O11;

  set O1/O3z/O8/O11 — no O2/O9/O10); the case is small: caps tokens 200000 /
  wall_min 10.
