# W4.08-control: Rugpull without the flag — exactly one replacement (gating)

Real pi run: bug-fix-merge-worktree (bfmw) on the **tt-ts** fixture
(`TEST_CMD` = `npm test`). Launched with `--context
no_relaunch_upon_rugpull=false` — the CONTROL variant of W4.08 (the
product default). The flag variant is the sibling row
`W4.08-no-relaunch`; each is a distinct terminal corridor.

## Seeded defect (BUG-T2 — what the fixture actually contains)

The tt-ts seed `BUG-T2` (SEEDS.md catalog) implants an **A2 two-module
date-handling bug**: `src/server.ts` parses user dates with
`new Date(dateStr).toISOString()` (full ISO datetime with timezone offset)
while `src/store.ts` `getByDateRange` compares with naive
`localeCompare` — an exact-date query excludes the expense near a day
boundary. Dormant in the baseline (no test submits a `date` field or uses
`?startDate=`/`?endDate=`). The fix normalizes dates to UTC midnight in
`server.ts` and switches `store.ts` to timestamp comparison. The task text
of the bug-fix run names this defect.

## Injection (machinery delta — documented, not silent)

Spec 08 §B W4.08: **chaos moves the target branch during finalize** — same
injection as W4.08-no-relaunch (tt-chaos `move-branch`/`colleague-commit` on
the TARGET ref, untyped → `chaos: null` + this contract; see
cases/tier2-traceability.md machinery deltas). Event-armed at
`step:finalize_merge:running` so the merger's expected-tip check fails with
`merge.target_moved` inside the finalize window.

## Expected (O10 unless noted)

- **Exactly one replacement:** the rugpull machinery detects the moved target
  (`run.rugpull_detected`), then relaunches EXACTLY once
  (`run.rugpull_relaunched` with a new run id). Zero, or more than one,
  replacement is the finding.
- **Context byte-identical minus bookkeeping (DC13):** the replacement run's
  context must equal the original run's context except for the
  replacement/bookkeeping keys (run id, parent/replacement linkage,
  timestamps, progress). Any drift in the user-supplied context (task,
  workflow, test_cmd, seed inputs) is the finding.
- **`self_merge_detected` if the first landing landed:** if the original run
  landed before the target move was detected, the replacement must detect the
  self-merge (the fix already landed) and refuse to re-apply — never a double
  application of the same diff. If the first run did not land, the replacement
  completes the merge normally.
- The replacement run's landing must carry the truthful annotation chain
  (O2); the merged tree must contain the fix.
