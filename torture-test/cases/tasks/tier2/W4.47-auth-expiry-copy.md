# W4.47: Auth expiry on the copy (REAL pi do-now, small tokens)

The TT env carries COPIED pi credentials at `$TT_HOME/.pi` (provisioned by
bin/tt-provision-home from the operator's `~/.pi`: `agent/settings.json`,
`agent/models.json`, `agent/auth.json`, ...). Mid-wave, the CONTAINED
credentials are INVALIDATED (never touching the REAL `~/.pi`), the do-now
launch's first round fails with a diagnosable auth error, the copy is
RESTORED, and the retried round completes.

## The pinned contract (spec 08 §K W4.47)

- The auth failure surfaces as a DIAGNOSABLE provider/auth error NAMING the
  harness (pi) — NEVER a silent zero-token "completion".
- NEVER a fallback to the REAL `~/.pi`: that fallback would be an
  isolation-breach S0. **O15** (production untouchedness, the campaign-level
  W0/W6 oracle — NOT a per-case oracle, deliberately not declared in the
  manifest) asserts the real credential file's atime/audit trail shows NO
  access during the invalidated window.
- Post-restore launch is CLEAN (the run completes).

## Wired operator-seam actions (S44a/S44b)

The manifest declares a single-run probe_sequence with the first-class
credential ops:

1. `invalidate_credentials` armed on `now` (fires as the run id resolves —
   BEFORE the first dispatch round): the controller replaces the CONTAINED
   home's `.pi/agent/auth.json` with an invalid provider-agnostic token,
   backing the original up beside it (`auth.json.tt-invalidated`). A SYMLINK
   target or any path resolving outside torture-test/var is refused
   (`operator-action-escape-refused`) — the REAL `~/.pi` is never written.
2. `restore_credentials` armed on `event:step.running` (fires when the
   RETRIED round's dispatch sets the step running — the invalidated first
   round exits before claiming (a provider-error instant-fail: zero output,
   no claim, no `step.worker_lost`), so the first `step.running` in the run
   is the relaunch's — the machinery equivalent of the operator's "restore
   the copy, launch again"): the controller consumes the backup and
   restores the original file byte-identical.

Every action records a per-action evidence record (op, target/backup paths,
sha256 before/after, observed effect, timestamps) and fails closed with the
distinct categories `invalidate-credentials-failed` /
`restore-credentials-failed` (missing/unreadable file, no-backup) — S18c
stop-the-run, never a silent vacuous verdict. The O15 real-credential
untouchedness check is the campaign-level W0/W6 oracle, recorded as the
required backstop.

## Expected

Diagnosable auth error naming pi while the copy is invalidated; zero real
`~/.pi` access (O15); clean completion after restore. Small real do-now spend
(`caps.tokens` 200k — the do-now unit; the invalidated round spends ~0).

The manifest row declares fixture `tt-ts` (the do-now runs against the
tt-ts work clone; the seeded content is irrelevant to the auth corridor —
the credential invalidation/restore IS the corridor).

## Boundaries

- The REAL `~/.pi` is READ-ONLY for this case (probed via atime/audit — O15);
  only `$TT_HOME/.pi` (the contained copy) is ever written.
