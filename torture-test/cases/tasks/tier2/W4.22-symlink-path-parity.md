# W4.22: Symlinked temp/var fixture paths — both directions, no false containment/validation failures (scripted, zero tokens; gating)

Scripted local-command case (zero tokens): the scenario cell
`scenarios/w4.22/symlink-path-parity/` exercises fixture paths in
SYMLINKED form vs REALPATH form, both directions (spec 08 §H W4.22 —
"Fixture paths in symlinked form (`/var/...`) vs realpath
(`/private/var/...`), both directions. No false containment/validation
failures in worktree checks, gates, TSTX hashing"). This is the darwin
`/var` → `/private/var` realpath defect class (DC30/DC44 family, spec 01
platform-facts table).

## Host-adaptation predicate (documented choice)

- `requires.platform = "darwin"`: the spec marks W4.22 `[darwin]` (or any
  host where a temp/var path is a symlink) — the canonical host-profile
  `platform` key is the honest gate. On a non-darwin host the case gates
  `NOT_RUN (predicate)` with evidence; the runner is written
  platform-generic (it models the `/var` → `/private/var` symlink itself),
  so the corridor machinery is validated on any symlink-capable host and the
  manifest-level predicate is judged by the controller.
- The cell performs PURE LOCAL path checks (git + containment machinery) and
  NEVER launches a workflow run, so it deliberately does NOT require
  `containment ["systemd-user-scope"]` — a darwin host (the matching
  platform) has no systemd user scope, and daemon-control uses its
  no-systemd fallback there. Requiring it would gate the case `NOT_RUN`
  forever on the very platform the spec targets.
- The standard cell shape minus containment: `capabilities ["node-sqlite"]`,
  `node_min 22`.

## What the scenario actually exercises (per spec)

The runner builds a scratch fixture repo at a REALPATH location under the
invocation dir and creates a SYMLINKED alias to it (modeling
`/var` → `/private/var`). It then runs the three check classes on BOTH path
forms and asserts parity — no false failure through the symlink:

- **Worktree checks:** `git -C <path> worktree list --porcelain` on the
  symlinked form and the realpath form — identical output, exit 0 both
  (the worktree check must not false-fail when the repo is reached through
  a symlinked path).
- **TSTX hashing:** `git -C <path> rev-parse HEAD^{tree}` on both forms —
  identical tree hash (the TSTX tree key is path-form-independent; a false
  failure would be a differing hash / an origin-repo identity split).
- **Containment / gates:** the path-form resolution against the contained
  root — BOTH forms resolve inside `torture-test/var/` (no false
  containment failure), and a CONTROL symlink pointing OUTSIDE the
  contained root is REJECTED (no false acceptance either — the gate still
  holds through the symlink).
- **Both directions:** (a) realpath → symlink (each check run with the
  realpath first, then the symlinked form) and (b) symlink → realpath
  (`fs.realpathSync` resolution, then the checks on the resolved path) —
  identical results every time.

## Expected

- The scenario cell runs PASS (exit 0) with `caps.tokens = 0` — zero
  tokens, no workflow launch, no real pi/hermes/dsh invocation.
- Worktree output, TSTX tree hash, and containment verdicts are identical
  for the symlinked form and the realpath form — no false containment /
  validation failures.
- The out-of-var control symlink is still rejected (fail-closed).
- The contained scripted daemon is left stopped; ports 5334/5338/5339 free.

## Boundaries

- The cell writes ONLY under `torture-test/var/` (scratch repo + symlinks);
  `env/tt-env.sh` and the real HOME are never touched.
