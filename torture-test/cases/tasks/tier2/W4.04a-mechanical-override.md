Real pi run: bug-fix-merge-worktree on tt-ts (seed `BUG-T4`). The mechanical
arm of the gate-override probe (puma M1–M4): `tt-chaos write-context` writes
`merge_gate=off` into the run's context via sqlite **before finalize**, so the

## Seeded defect (BUG-T4 — what the fixture actually contains)

The tt-ts fixture's seed `BUG-T4` (SEEDS.md catalog) implants an **A4 performance
bug** in `src/store.ts`: `getByCategory` replaces the O(n) `Array.filter()` with
an O(n²) nested-loop implementation using `JSON.stringify` comparisons — ~4M
stringify calls for 2,000 expenses (~180ms vs sub-millisecond). The regression
test creates 2,000 expenses across 5 categories and asserts completion in under
50ms. The fixer must restore the O(n) filter.

## Injection (machinery delta — documented, not silent)

The spec's arming is `tt-chaos write-context --key merge_gate --value off` on
the run's context row **before finalize dispatches** (armed on
`step:finalize_merge:pending`). `write-context` is implemented in bin/tt-chaos
but the typed chaos block currently exposes only `sigstop_sigcont |
kill-harness | kill-daemon | delete-tstx-row`; exposing `write-context` is a
follow-up execution story (see cases/tier2-traceability.md machinery deltas).
This case declares `chaos: null` and carries the injection contract in this
task text. The injection must happen AFTER the verify step attests and BEFORE
the finalize step reads the gate policy.
