# W4.12: Port squatter on the daemon control port during restart (scripted, zero tokens; gating)

Scripted local-command case (zero tokens): the scenario cell
`scenarios/w4.12/port-squatter/` choreographs the spec 08 §C W4.12 **retrying
binder** against the CONTAINED scripted daemon's control port, driving the
PRODUCT `tamandua restart --force` command.

## What the scenario actually exercises (per spec arm)

The choreography (the "naive pre-bound squatter just exits — first-draft
mechanism didn't work" failure mode is explicitly pinned):

1. The scripted daemon is RUNNING and owns the control port.
2. A **retrying binder** (the squatter) starts BEFORE `tamandua restart`: it
   loops on EADDRINUSE (30 ms retry) while the daemon owns the port — it is
   asserted to be ALIVE and to have observed at least one EADDRINUSE (never
   exits like the naive first draft).
3. `tamandua restart --force` stops the services; when the daemon releases the
   port at the stop→start barrier (the stop's pidfile unlink), the squatter's
   next retry **WINS the bind** (held marker).
4. The daemon's start attempt fails with a **clean EADDRINUSE diagnosis** in
   the daemon log; the daemon cleans its pidfile and exits — **no half-up
   daemon with a live pidfile (O13)**; the squatter (not the daemon) owns the
   port.
5. The runner CAPTURES the failed-start evidence, then **releases** the
   squatter (it closes its socket and exits 0).
6. A retry `tamandua restart --force` **succeeds**: all services restart, the
   control plane is reachable, the pidfile is live.

## Spec-vs-machinery notes (documented, not silent)

- The spec targets the real daemon's control port **4339**; the scripted case
  runs the identical choreography on the CONTAINED scripted control port
  **5339** (scripted kind ports 5334/5338/5339 per daemon-control) — a
  contained-port substitution, never a production-port touch.
- The retry is invoked as `tamandua restart --force` (the product command);
  `--force` is used so a leftover active run in the shared contained ledger can
  never wedge the choreography.
- **Observed product behavior (recorded, not a trim):** the first restart's
  stop phase deletes `~/.tamandua/port` (dashboard) and `mcp-port`, and the
  failed daemon start never rewrites them — a retry `tamandua restart` then
  falls back to the production DEFAULT ports (3334/3338) and fails on those
  production listeners. The scenario restores the contained configured ports
  (5334/5338 per tt-env-scripted.sh) before the retry so the corridor under
  test stays the port-squatter recovery; the fallback is recorded as an
  observed product behavior.
- **O13 (no half-up daemon with a live pidfile) is NOT a declared oracle** —
  the implemented oracle set is O1/O2/O3z/O4/O8/O9/O10/O11/O16 (tier1-oracle-
  hygiene fails closed on declared-but-missing oracles). O13 is a REQUIRED
  backstop named here + in the traceability, and the scenario cell itself
  asserts the pidfile/liveness + port-ownership evidence. The manifest
  declares the local-case oracle set (O1/O3z/O11).
