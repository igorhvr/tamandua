## What the fixture actually contains (FEAT-G1)

(Seeded Features table): `NewPool` must read `TTGO_MAX_WORKERS` and override

to the parameter. The acceptance boundaries are pinned there (env precedence,

canonical suite. There is NO seeded bug in the green baseline — the fdmw's job
is to implement the feature story-by-story and land it.

## Injection (machinery delta — documented, not silent)

Spec 08 §B W4.06: a colleague commits an **unrelated change to the target
branch** at ~T+15m and ~T+45m of the run's lifecycle, so the run's base
moves under it while the feature branch is still in flight. The injection is
tt-chaos `colleague-commit` (a competing commit from a second-clone
perspective) — implemented in bin/tt-chaos but **not** exposed in the typed
manifest chaos block (which offers only `sigstop_sigcont | kill-harness |
kill-daemon | delete-tstx-row`). This case carries `chaos: null` and the
injection contract lives here; wiring the block type is a follow-up execution
story (see cases/tier2-traceability.md machinery deltas). Per the wave-4
injection discipline, the commits are event-armed (never a bare sleep):
commit 1 fires when `step:developer:running` (≈ T+15m of a 138-min fdmw
lifecycle), commit 2 when `step:verify:running` (≈ T+45m). The commits must
touch files the feature work does NOT touch (e.g. `README.md`), so they are
unrelated to the run's diff.

## Expected (O10 unless noted)

- **Rebase-loopback:** the merger's fast-forward/tip check detects the moved
  target and routes through the retry/`REBASED: true` corridor → the workflow
  re-runs `test` on the rebased branch → the tree is re-verified → the run
  lands. The landing must carry the truthful annotation chain (O2).
- **Reroute budget respected:** the rebase-loopback consumes reroutes from the
  fdmw finalize budget (`max_reroutes: 8`), never more than the corridor
  needs; a budget-exhaustion failure here is a product finding.
- **Zero false rugpulls:** base identity must come from the RECORDED refs
  (base-branch sha captured at launch), never from a live `HEAD` read of the
  moving target — a colleague's unrelated commit is a rebase event, NOT a
  rugpull; `run.rugpull_detected` firing for it is the finding.
