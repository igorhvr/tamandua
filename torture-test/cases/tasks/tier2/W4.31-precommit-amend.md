# W4.31: Tree-rewriting pre-commit hook — the attested tree is what lands

Real pi run: bug-fix-merge-worktree (bfmw) on **tt-ts**, seed **BUG-T1** (the
SEEDS.md catalog's A1 off-by-one defect in `src/store.ts` `getByCategory`).
Spec 08 §F W4.31 (T1): a **tree-rewriting pre-commit hook** is installed into
the working clone's `.git/hooks/` (executable; it `git add`s a REWRITTEN line
into every commit). Scope honestly re-drawn: the hook fires on the FIXER's
commits (the final landing is plumbing — merge-tree/commit-tree/update-ref —
and runs no hooks, so it cannot create a landing-time mismatch).

## The injection (wired this story — real reset-hook arming)

- **Fixture asset:** `torture-test/fixtures/hooks/pre-commit-amend.sh`
  (executable). On every commit it rewrites the single line of the tracked
  marker file `src/pre-commit-amend.marker.txt` (increments the counter) and
  `git add`s it — every commit carries the hook's mutation. Fail-closed: any
  hook failure aborts the commit loudly.
- **Reset hook:** `cases/hooks/reset-w4.31-precommit-amend.sh` (the spec's
  W4.31 mechanism) installs the asset into the working clone's
  `.git/hooks/pre-commit` (mode 0755) and plants the TRACKED marker baseline
  (committed at `pre-commit-amend: 0` BEFORE the hook is installed, so the
  baseline tree is deterministic and the fixer's commits rewrite it). It then
  ASSERTS the installation — hook present, executable, byte-identical to the
  asset, marker baseline committed — and fails closed otherwise (never a
  silent non-install).
- The managed run worktree shares the work clone's git-common-dir, so the
  installed hook fires on the fixer's commits in the run worktree.

## The corridor asserted

The tree the verifier attests (post-hook) is what lands:

- **`TESTED_TREE` is computed AFTER the hook's mutation** — the verifier runs
  `npm test` on the committed tree that already includes the rewritten marker
  line, so the attestation chain stays truthful end-to-end.
- **Any step caching a pre-hook tree** (agent-reported vs actual) surfaces as
  a mismatch finding: `MERGED_TREE != TESTED_TREE` must fail loudly (the O10
  attestation comparison), never land silently.
- The landing-time-mutation case remains **W4.03** (post-attestation branch
  commit under a drain barrier) — this case pins the fixer-commit corridor
  only.

## The task

Fix the seeded defect (BUG-T1: category filter off-by-one) so
`getByCategory` returns ALL matching expenses, run `npm test`, and land —
NORMALLY. Every commit you make will carry the pre-commit hook's marker
rewrite; that is the injection under test. Do not remove or disable
`.git/hooks/pre-commit`, and do not delete `src/pre-commit-amend.marker.txt`.

## Expected

- The run completes and lands with `MERGED_TREE == TESTED_TREE` where
  `TESTED_TREE` includes the post-hook marker — the attestation chain is
  truthful.
- **Finding:** any step that attested a PRE-hook tree (e.g. a cached tree
  from before the hook's mutation) surfaces as a `MERGED_TREE != TESTED_TREE`
  mismatch — a silent green landing of a tree whose attestation is stale is
  the violation.
- The marker file's counter advances with the fixer's commits (visible in the
  landed tree).

## Boundaries

- Do not modify `operator-notes.local`, `seeds/`, or files under `probes/`.
- The pre-commit hook and the marker file are the INJECTION — keep them
