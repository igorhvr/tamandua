## Premise the cell pins

Spec 08 §G W4.33 leg (d) (`W4.33d-reroute-exhaustion-resume`) was authored as
reroute-EXHAUSTION: a persistent consumer-rejection condition (a colleague
target move re-armed per finalize attempt) exhausts `max_reroutes` so the run
permanently fails and the probe resumes it. Three real-campaign redesigns
(S29 typed chaos, S36 per-attempt re-arm, mac campaign #1) never made the
premise fire in a real run: the product's reroute machinery **absorbs** the
injected target moves gracefully — each move reroutes the finalize, and once
the pressure stops the run lands. The real premise is therefore not honestly
reachable, and the product behavior it exposed is the resilience property
worth pinning.

**This cell pins the graceful absorption (per igorhvr's S49 triage — item 6):
a colleague target-move injected at the finalize is absorbed by the reroute
corridor — RED on regression of that absorption.** If the product stops
absorbing (the first injected move permanently fails the run, the reroute
corridor wedges, the move is silently swallowed into a wrong landing, or a
single fault produces two landings), the cell goes RED.

## Seeded defect (BUG-T4 — what the fixture actually contains)

The tt-ts seed `BUG-T4` (SEEDS.md catalog) implants an **A4 performance
defect** in `src/store.ts`: `getByCategory` becomes O(n²) (nested loops +
`JSON.stringify` comparisons, ~4M calls for 2,000 expenses). Dormant in the
baseline; the regression test creates 2,000 expenses and asserts completion
under 50ms.

## Injection / deterministic corridor (absorption)

The colleague target-move is the **typed `move-branch` chaos block** in the
manifest (US-004 premise redesign machinery, kept):

```json
{"type":"move-branch","target":"origin_target_ref","trigger":"step:finalize_merge:running",
 "operator":"tt-chaos","ref":"refs/heads/seed/BUG-T4","repeat":2,"interval_s":3,
 "wait_timeout_s":900,"rearm":true,"rearm_hold_s":2}
```

`rearm: true, rearm_hold_s: 2` fires move 1 two seconds after the FIRST
`step:finalize_merge:running` occurrence (the scripted merger's tip capture
precedes the move) and move 2 two seconds after the SECOND occurrence (the
rerouted attempt) — each finalize attempt observes a moved tip exactly once,
then the budget (2 moves) is spent and the target stabilizes.

The scripted **merger is a behavior ARRAY** (see the scenario behaviors file)
that makes the absorption deterministic:

1. **attempt 1 — retry behavior:** captures the origin tip, sleeps a window
   the re-armed move lands in, runs the REAL `tamandua merge-branch` with the
   OLD tip (`includeCommandOutput` off; `|| true` — merge-branch exits 2 on a
   moved tip) → `merge.target_moved` fires → replies `STATUS: retry` → the
   finalize step's `retry_step: verify` reroutes (one `step.rerouted`).
2. **attempt 2 — done behavior:** runs merge-branch with the CURRENT (stable)
   tip → `STATUS: done` → the landing proceeds → `run.completed`.

## Expected (pinned, mechanical)

- **Reroute ABSORBS the injected move:** exactly the injected fault is
  absorbed — `merge.target_moved` fires, the run reroutes (≥ 1
  `step.rerouted`), the re-attempt lands, and the run **completes**
  (`run.completed`) with a single truthful `merge.landed` annotation.
- **Never exhausted, never wedged, never double-landed:** the run does NOT
  permanently fail on the absorbed move (`run.failed` absent), does not
  exhaust the reroute budget, and the landing is single.
- **The absorption is RED on regression:** a product regression that fails the
  run on the first absorbed move, wedges the reroute corridor, or lands
  twice fails the cell (run not completed / O1 / O2-style finding).
- Zero tokens (scripted-pi runtime + system tripwire).
