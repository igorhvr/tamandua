## Injection (drain-armed evidence deletion, same corridor as W4.01)

1. `workflow pause --drain` fires while `verify` is still running

2. `tt-chaos delete-tstx-row --tree <TESTED_TREE>` fires on
   `step:finalize_merge:pending` and deletes the tested tree's suite evidence

### T2.1 US-010 premise corrections (scripted arm, no assertion weakened)

- **The deletion targets the REAL suite ledger (`suite_results`), not a
  `tstx` table.** The product schema has no `tstx` table — the tamandua-test
  shim's suite rows live in `suite_results` (tree_hash/origin_repo/run_id/
  step_id). tt-chaos's `delete-tstx-row` previously deleted from the
  nonexistent `tstx` table and errored (`no such table: tstx`); it now
  deletes the tested tree's `suite_results` rows (a legacy `tstx` table is
  also honored when present). For the SCRIPTED arm the verifier produces no
  suite row at all (the missing-evidence premise), so the deletion is a
  no-op — the corridor's missing-evidence outcome comes from the verifier
  never running a suite, exactly as authored.
- **`step:<step-id>:<state>` chaos markers now match the step id.** The
  manifest/phase markers name WORKFLOW STEPS (`step:finalize_merge:pending`),
  but tt-chaos's `checkStepMarker` matched only `agent_id LIKE %role%` (the
  finalize step's agent is `merger`), so the trigger never fired
  (`EXIT_TRIGGER_NEVER`). It now matches `step_id = ? OR agent_id LIKE ?`,
  mirroring the controller's `probeStepMarkerSatisfied`.
- **The verifier holds the running window with `sleep 10`.** The canned
  scripted verifier completes in <1s, so the 500ms probe poll can never
  observe `step:verify:running` and the pause_drain never arms
  (`probe-trigger-unreached`). A `sleep 10` command holds the step in the
  running state for the drain to arm — it produces NO suite evidence, so the
  missing-evidence premise is unchanged.

failure: re-proof #2 (campaign-20260818T145745610Z, fresh var, bare
