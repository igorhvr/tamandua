## What the fixture actually contains

The tt-ts fixture's seed `BUG-T1` (SEEDS.md catalog) implants an **A1 off-by-one
in `src/store.ts`** (see `W4.01-missing-evidence-reroute.md` for the full
symptom). The scripted fixer's behavior is canned via the scripted behaviors
file (TAMANDUA_SCRIPTED_BEHAVIORS): it makes a fix-shaped edit that DELETES a
test file (`src/store.test.ts` or a named regression test) and inverts an
assertion, so the suite is broken AND the test inventory is destroyed.

## Injection (drain-armed evidence deletion, same corridor as W4.01)

1. `workflow pause --drain` fires while `verify` is still running
   (`step:verify:running`); the drain parks dispatch with `finalize_merge`
   promoted to pending.
2. `tt-chaos delete-tstx-row --tree <TESTED_TREE>` fires on
   `step:finalize_merge:pending` and deletes the tested tree's TSTX evidence
   row — the evidence is now MISSING, not red (the fixer already broke the
   suite; the deletion hides the break).
3. The daemon resumes and finalize dispatches with `missing` evidence under
   the default gate.

The manifest's `chaos.tree` carries the sentinel `TESTEDTREE` — the execution
machinery resolves it to the run's attested `TESTED_TREE` before arming
tt-chaos.

## Oracle delta (documented, not silent)

O17 (test-inventory oracle) is not yet implemented in the oracle registry
(`torture-test/oracles/` ships O1/O2/O3z/O4/O8/O9/O10/O11/O16). The
declared-oracle hygiene gate (tier1-oracle-hygiene.test.ts) FAILS CLOSED on a
declared-but-missing oracle, so O17 is deliberately NOT declared in this
case's manifest oracle list. It is a REQUIRED backstop named in this task: the
case's landing evidence must be reviewed against the test-inventory
regression (deleted/weakened tests) by the O17 oracle once it ships, at which
point the manifest oracle list is extended and the case flips to gating on it
(see cases/tier2-traceability.md machinery deltas).
