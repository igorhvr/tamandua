# W4.28: TSTX cross-repo collision — two INDEPENDENT bares, zero cross-repo replay

Real pi run: bug-fix-merge-worktree (bfmw) on **tt-ts**, seed **BUG-T1** (the
SEEDS.md catalog's A1 off-by-one defect in `src/store.ts` `getByCategory`).
Spec 08 §F W4.28 (T1): the TSTX ledger keys rows per `origin_repo`, and two
clones of the same golden that share a `git-common-dir` ancestry (or normalize
to the same origin identity) can silently replay each other's ledger rows —
the O9 "catastrophic and silent" case. The construction matters: this case
builds **two INDEPENDENT bares** (`git init --bare` twice, identical content,
distinct origin identities, byte-identical HEAD trees) so the cross-repo
replay gate actually tests something.

## The two-independent-bares construction (task-carried arming)

The case's **reset hook** (`cases/hooks/reset-w4.28-independent-bares.sh`)
runs after provisioning and builds the spec'd construction:

1. **Bare-A lineage:** the provisioned working clone (`tt-ts`) cloned from the
   golden — the run's `--worktree-origin-repository`.
2. **Bare-B (INDEPENDENT):** created from scratch with `git init --bare`
   (never a directory copy — a copy would share git-common-dir ancestry, the
   spec's trap), then the IDENTICAL content is pushed to it
   (`git push <bare-B> HEAD:refs/heads/<branch>`).
3. **Clone-B:** an independent working clone of bare-B (`tt-ts-clone-B`).
4. The hook VERIFIES the construction (fail-closed): `rev-parse HEAD^{tree}`
   is **byte-identical** across the two clones, and the git-common-dir
   realpaths (the `getOriginRepo`-equivalent identities) resolve to
   **distinct** paths — a symlink//private/var normalization collapse is the
   O9 trap and fails the reset.

## The zero-cross-repo-replay gate (O9 — the oracle is TSTX-keyed, never prose)

The corridor asserted (operator choreography, documented not silent — there is
no controller op for the cross-repo replay check):

1. Let the bfmw run proceed normally against the provisioned clone (bare-A
   lineage). The run's `verify` step executes `npm test` and the shim records
   a TSTX ledger row keyed to bare-A's `origin_repo` path.
2. **Re-run the SAME suite in Clone-B** (byte-identical HEAD tree, DISTINCT
   origin_repo) via the contained tamandua-test shim. Because the origin
   identities differ, the lookup must MISS bare-A's row and the suite must
   **EXECUTE fresh** — a cache hit would be a **silent cross-repo replay**
   (the "catastrophic and silent" finding).
3. Assert the ledger rows are keyed **per origin_repo**: bare-A's row and
   clone-B's row coexist under distinct keys; neither replays the other.

## Expected

- The run completes and lands the fix with a truthful attestation chain; the
  TSTX row for the tested tree is recorded against bare-A's origin identity.
- **Zero cross-repo replay:** the clone-B re-run executes (never
  `TAMANDUA-TEST CACHED` against bare-A's row). A silent replay — rows keyed
  to a collapsed/normalized origin identity — is the O9 finding.
- The two bares resolve to distinct origin identities even though their HEAD
  trees are byte-identical.
