# W4.20: `tamandua update` repo-state classification — behind/ahead/diverged/network-error (scripted, zero tokens; gating)

Scripted local-command case (zero tokens): the scenario cell
`scenarios/w4.20/update-repo-state-classification/` provisions local
source-checkout fixtures (the tier0 w4.49 delivery shape: bare remote +
seed clone + per-leg installed clones) and runs `tamandua update` against
FOUR repo-state legs (spec 08 §E W4.20 — "tamandua update against
behind/ahead/diverged/network-error repo fixtures").

## What the scenario actually exercises (per spec, four distinct outcomes)

| Leg | Fixture state | Classification | Outcome |
|-----|---------------|----------------|---------|
| behind | remote advanced; installed clone behind | pull `--ff-only` succeeds | exit 0, "Tamandua update complete.", HEAD advances, build-and-install runs |
| ahead | installed clone has a LOCAL commit the remote lacks | `no_change` — a PURE-ahead checkout is NOT divergence: `git pull --ff-only` no-ops ("Already up to date") | exit 0, "already at ...", every mutating phase skipped (no build, no install, no service restart) |
| diverged | BOTH sides advanced (local commit + remote commit) | `refused_diverged` (pull fails non-fast-forward; ahead + remote reachable) | exit 1, "Not pulling." — remote-only commit count >= 1 distinguishes it from ahead |
| network-error | origin points at an unreachable remote | `pull_failed` (remote unreachable) | exit 1, "git pull failed ... Aborting update." |

- **DC31 — zero destructive steps (asserted mechanically):** every
  non-mutating leg (ahead no-op, diverged refusal, network-error refusal)
  snapshots the installed clone before the update (HEAD, a planted tracked
  modification, a planted untracked file, the executable dist tree
  inventory, git status) and asserts it BYTE-IDENTICAL after: HEAD
  unchanged, the local commit survives, build-and-install was NEVER
  executed (no build marker), no `.git/MERGE_HEAD` / `.git/rebase-merge` /
  `.git/rebase-apply` residue, no services disturbed. (The diverged and
  network-error refusals additionally exit non-zero per the spec's
  "non-zero exit on divergence refusal".)
- **HARN (KNOWN-OPEN, NOT gated):** the spec wave gate registers "update
  never mutates a repo it doesn't own" as a KNOWN-OPEN reproduction
  (expect to reproduce; confirm the register entry and do not gate). The
  four legs above are the authored scope; the HARN seam is documented in
  cases/tier2-traceability.md, never silently trimmed.
- The contained scripted daemon is stopped before the legs so the update's
  service snapshot is empty — the legs stay purely about git
  classification (no daemon stop/restart races).
