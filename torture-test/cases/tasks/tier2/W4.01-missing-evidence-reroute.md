# W4.01: Missing evidence reroute — drain-armed delete-tstx-row (gating)

Real pi run: bug-fix-merge-worktree on tt-ts (seed `BUG-T1`). This is the
wave-4 merge-gate & evidence-corridor scenario where the tested tree's suite
evidence row is DELETED from the TSTX ledger while the merge is parked under a
drain barrier, so the finalize step sees `missing` (not red) evidence.

## Seeded defect (BUG-T1 — what the fixture actually contains)

The tt-ts fixture's seed `BUG-T1` (SEEDS.md catalog) implants an **A1 off-by-one
in `src/store.ts`**: `getByCategory` uses a manual `for` loop with condition
`i < this.#expenses.length - 1`, skipping the last element of the internal
array. The existing 59-test baseline stays green because no test's last element
matches the queried category; the fixer must write the regression test that
catches it (3 Food expenses with a Transport interspersed so the last element
is a matching Food — `getByCategory('Food')` returns 2 instead of 3).

## Injection (drain-armed evidence deletion)

Deterministic arming, per spec 08 §A W4.01:

1. `workflow pause --drain` fires **while `verify` is still running**
   (`step:verify:running`). A pause issued "right after" verify completes
   races finalize dispatch and can lose — the probe must arm while verify is
   mid-flight.
2. Verify completes; the drain parks dispatch with `finalize_merge` promoted
   to **pending** (the `draining_pause` scheduling state).
3. `tt-chaos delete-tstx-row --tree <TESTED_TREE>` fires when
   `finalize_merge` reaches `pending` (`step:finalize_merge:pending`) and
   deletes the TSTX ledger row for the tested tree (bfmw's evidence producer
   is `verify`; there is no `test` step).
4. The daemon resumes and finalize dispatches with `missing` evidence.

The manifest's `chaos.tree` carries the sentinel `TESTEDTREE` — the execution
machinery resolves it to the run's attested `TESTED_TREE` (the verifier's
`TESTED_TREE:` output line) before arming tt-chaos; the typed block requires a
literal tree hash.
